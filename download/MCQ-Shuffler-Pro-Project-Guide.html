How to use this guide
"Edit one card" — the fast path

This guide is an edit-locator: it maps every visible card and button on mcq-shuffler-pro (https://afnan-samin.github.io/MCQ_Shuffler_Pro/) to the exact file and line where it lives. The project was deliberately re-shaped around a mother / child architecture, so a small, targeted edit almost never touches the whole project.

Golden rule — find the card in Part 3, open its file, change only that card's markup or text. Buttons push events up to src/app/page.tsx, which is the single wiring layer: UI lives in src/components/mcq/, all logic lives in src/lib/mcq/. If your edit changes a visible label, sync the E2E selectors listed in the Appendix in the same commit.

Conventions used: M = mother (shared component used by several modes — edit it and every consumer changes); C = child (belongs to one mode only). Line numbers were verified against the current codebase (commit series ending 0d8188e). All button labels are quoted byte-exact from code so you can rg-search for them.

Part 1
Site flow at a glance

The user journey has four beats: upload → mode selection → work view → download. After staging files, exactly three mode buttons appear; each mode owns its own input, option and result cards; and every download card carries the same two shared widgets — the font settings card and the DOCX/PDF format toggle.

Part 2
The Mothers — shared infrastructure

Mothers are the pieces every mode leans on. Editing a mother changes every consumer at once — that is their purpose. Treat repack-docx.ts, docx-xml.ts and parser.ts as protected mothers: they guarantee the "formatting kept exactly" promise, and any edit there must run the full unit-test suite (scripts/test-*.ts, 530+ assertions).

siteTheme — one-place theme controlMsrc/config/theme.ts292 lines · + theme-css.ts 106 lines

What: the single file that controls all site fonts, colors, popups and corner radius. siteTheme (142): fonts (sans/serif/mono/bengali), colors.light + colors.dark (background, card, primary, muted, destructive + destructiveForeground, border, ring, brand 50–950), radius.base (one knob, sm/md/lg/xl derived), popup (radius/shadow/border/backdropBlur). theme-css.ts turns it into :root {--st-*} + .dark {--st-*} CSS; src/app/layout.tsx (67) injects the tag; globals.css re-points all Tailwind/shadcn tokens at those vars.

Iron rule: edit theme.ts ONLY — never edit theme-css.ts or the var chain. The file's bottom comment carries the three official recipes:

① Site font everywhere — edit fonts.sans (147), e.g. 'Verdana, "Noto Sans Bengali", sans-serif'; for a web font add it via next/font in layout.tsx with variable: "--font-myfont", put it on <html>, then use sans: 'var(--font-myfont), …'. Keep a Bengali-capable font in the stack. ② Brand color — edit colors.light.brand 600 (solid fills) + 700 (hover), tune neighbors; every bg-brand-600/text-brand-700 class site-wide follows. ③ Popups — edit popup.radius ("0px" sharp / "12px" round) and popup.shadow; toasts + select dropdowns follow.

docxBlobToPdfBlob — PDF exportMsrc/lib/mcq/pdf-export.ts238 lines

Exports: DownloadFormat = "docx" | "pdf" (35) · PDF_MAX_PAGES = 300 (40, memory guard with English abort message) · pdfFileNameOf(name) (50) · docxBlobToPdfBlob(docx, baseName) (80) — 100% in-browser: docx-preview render → html2canvas-pro capture (scale 2 ≤100 pages, 1.5 ≤300) → jsPDF A4; canvases taller than A4 are sliced one-page-per-A4-chunk so continuous documents paginate correctly.

4.1 · Shuffle mode — single .docx flow

  1. Upload on UploadFirstCard → stageFiles (page 305) → isValidDocxZip (file-pipeline 33) rejects fake docx files with an English toast.
  2. Click 🔀 MCQ Shuffle on ModeTabs → changeMode (397) → carryToMode (469) → handleShuffleFiles (1360) → single file → handleDocxFile (629) → runFilePipeline + prepareShuffleXml (125) strips color headers + non-MCQ lines → parseDocxXml (docx-xml 426) → state docx.
  3. DocxDetectCard: selection buttons → selectAll / selectNone / selectRange (1099–1111); broken serial → 🔧 Fix serial & download .docx (1..N) → handleDocxSerialFix (1042) → buildSerialFixedDocxBlob (docx-exporter 190) → repackDocxRemapped → finalizeDownload (376); or enable Run as-is.
